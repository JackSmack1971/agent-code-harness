# Documentation Rules

- Documentation describes executable reality; it does not create runtime authority.
- Generate or derive registry tables from canonical machine-readable sources where practical.
- Mark version-sensitive implementation claims with their research artifact/version scope.
- Do not document degraded fallback as equivalent security.
- Keep normative language aligned with contracts: MUST/SHOULD/MAY only when the source contract supports it.
- Never claim phase closure, support, or verification without current evidence.
